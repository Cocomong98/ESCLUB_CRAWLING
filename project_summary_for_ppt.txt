## FC Online 감독모드 데이터 크롤러 및 프론트엔드 연동 프로젝트 (PPT 발표 자료)

### 1. 프로젝트 개요 (슬라이드 1)

*   **프로젝트명**: FC Online 감독모드 데이터 크롤러 및 프론트엔드 연동 프로젝트
*   **목표**: 특정 이용자 그룹의 FC 온라인 데이터를 자동으로 수집/가공하여 **핵심 데이터(`JSON`)를 생성**하고, 이를 **별도의 프론트엔드 애플리케이션에 제공**하여 최종 사용자에게 시각화된 정보를 제공
*   **기대효과**:
    *   데이터 수집(크롤러)과 사용자 화면(프론트엔드)을 분리하여 독립적인 개발 및 유지보수 용이
    *   '채굴 효율' 등 가공된 지표를 포함한 JSON 데이터를 API처럼 제공
    *   주기적인 데이터 아카이빙을 통한 시즌별 성과 추이 분석 기반 마련

### 2. 전체 아키텍처 (슬라이드 2)

```
+--------------+      +-----------------------+      +--------------------------------+      +----------------------+
|  Input Data  |----->|   Crawler Backend     |----->|     Data API (JSON File)       |----->|   External Frontend  |
|  (urls.txt)  |      |       (app.py)        |      | (current_crawl_display_data.json)|      |     (Build File)     |
+--------------+      +-----------------------+      +--------------------------------+      +----------------------+
       |                        |                                |                               |
 [감독 URL 목록]      [데이터 수집/가공/저장]                [가공된 통계 데이터]                  [사용자용 최종 화면]
```

*   **Crawler Backend (본 프로젝트)**:
    *   `urls.txt`를 기반으로 `Selenium`을 이용해 FC 온라인 데이터 크롤링
    *   `Flask`를 통해 크롤링 실행을 제어하고, 내장된 뷰로 데이터를 확인할 수 있는 환경 제공
    *   핵심 결과물인 `current_crawl_display_data.json` 파일을 생성 및 업데이트
*   **External Frontend (별도 프로젝트)**:
    *   주기적으로 서버에 업로드되는 `current_crawl_display_data.json` 파일을 데이터 소스로 사용
    *   React, Vue 등 모던 프론트엔드 프레임워크로 빌드된 정적 웹 애플리케이션
    *   사용자 친화적인 UI/UX로 최종 데이터 시각화 담당

### 3. 백엔드 주요 기능 및 프로세스 (슬라이드 3)

1.  **크롤링 실행**: 내장된 웹 UI 또는 스케줄러를 통해 크롤링 프로세스 시작
2.  **데이터 수집 (Crawling)**:
    *   `app.py`가 `urls.txt`를 읽어 크롤링 대상을 리스트업
    *   Selenium WebDriver (Headless Chrome)를 사용하여 각 감독의 URL에 순차적으로 접근
    *   **주요 수집 항목**: 현재/지난 시즌 전적 (승, 무, 패, 승률), 구단 가치 (BP)
3.  **데이터 가공 및 분석**:
    *   **'채굴 효율'** 계산: `승 * 7 - 무 * 3 - 패` 공식으로 자체 효율 지표 산출
    *   **순위 산정** 및 **순위 변동 계산**
4.  **결과 저장 및 데이터 제공**:
    *   **핵심 데이터 제공**: 외부 프론트엔드가 사용할 `current_crawl_display_data.json` 파일 생성
    *   **데이터 아카이빙**:
        *   `archive/YYYY-MM-DD.json`: 일별 데이터 보관
        *   `user/{player_id}/...`: 사용자별 데이터 히스토리
    *   **내장된 데이터 확인용 뷰**: `/results_table` 엔드포인트에서 생성된 JSON 데이터를 즉시 확인 가능

### 4. 백엔드 핵심 코드 분석 (`app.py`) (슬라이드 4)

*   **`/crawl` 라우트**:
    *   크롤링을 트리거하는 API 엔드포인트.
    *   `ThreadPoolExecutor`를 사용해 크롤링 작업을 병렬로 실행하여 시간 단축.
    *   오류 발생 시, 최대 10회 재시도하는 로직(`_robust_crawl_manager`)으로 안정성 확보.
    *   모든 후처리 완료 후, 최종적으로 `current_crawl_display_data.json` 파일을 업데이트.
*   **`_crawl_single_manager` 함수**:
    *   단일 감독의 데이터를 Selenium으로 크롤링하는 핵심 로직.
    *   `WebDriverWait`를 사용해 동적 컨텐츠 로딩에 안정적으로 대응.
    *   정규식(re)으로 텍스트에서 필요한 정보를 정교하게 추출.
*   **`/results_table` 라우트**:
    *   **개발/디버깅용 기능**.
    *   `_generate_results_html` 함수를 통해 `current_crawl_display_data.json`을 읽어 HTML 페이지를 동적으로 생성.
    *   프론트엔드 프로젝트를 거치지 않고 크롤링 결과를 빠르게 확인할 수 있는 **내장 데이터 뷰어** 역할.

### 5. 프로젝트 구성: 백엔드와 프론트엔드 (슬라이드 5)

*   **Part 1: 크롤러 백엔드 (본 프로젝트)**
    *   **역할**: 데이터 생산자(Data Producer). FC 온라인 웹사이트로부터 원천 데이터를 수집하고, 가공하여 의미 있는 지표가 포함된 `JSON` 데이터를 만드는 것을 책임.
    *   **기술 스택**: Python, Flask, Selenium.
    *   **주요 산출물**: `current_crawl_display_data.json`
*   **Part 2: 외부 프론트엔드 (별도 프로젝트)**
    *   **역할**: 데이터 소비자(Data Consumer). 백엔드가 제공한 `JSON` 데이터를 받아, 최종 사용자를 위한 시각적으로 뛰어난 웹 페이지를 렌더링하는 것을 책임.
    *   **데이터 연동 방식**: 서버에 업로드된 `JSON` 파일을 `fetch` API 등을 통해 비동기적으로 로드.
    *   **기술 스택**: React/Vue/Angular 등 JavaScript 프레임워크 + CSS/Tailwind 등.

### 6. 프로젝트 발전 과정 (슬라이드 6 - Appendix)

*   **1단계 (fconline_crawler.py)**: 단일 파일 내 순차적 로직의 커맨드라인 크롤러.
*   **2단계 (ap.py + templates)**: Flask 웹 서버 도입, 병렬 처리 및 정적 HTML 결과물 생성.
*   **3단계 (app.py - 현재)**: **데이터 생성(Backend)과 소비(Frontend)의 역할 분리**. 동적 데이터 확인용 뷰를 내장한 안정적인 데이터 크롤러로 발전.

---
**발표 시 참고사항**:
*   백엔드와 프론트엔드가 **분리된 아키텍처(Decoupled Architecture)**의 장점(독립적 배포, 기술 스택의 유연성)을 강조.
*   크롤러는 '데이터 제공'에만 집중하고, 프론트엔드는 '사용자 경험'에만 집중하는 **'관심사의 분리(Separation of Concerns)'** 원칙이 어떻게 적용되었는지 설명.
*   '채굴 효율'이라는 독자적인 지표가 어떻게 데이터 가공을 통해 부가 가치를 창출하는지 어필.
